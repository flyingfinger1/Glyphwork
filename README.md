# Glyphwork

Clickable, pixel-positioned GUIs inside the vanilla **dialog** screen (Paper 26.3), no client mod.
The whole GUI is one `plain_message`; the plugin generates a resource pack with bitmap fonts,
serves it from an embedded HTTP server and sends it on join. See [SPEC.md](SPEC.md).

**Status: M3** (primitives proven in a vanilla client, autotiled skins, public scene API). Other
plugins build screens with panels, labels, buttons, lists, grids, navigation and text input:
[docs/api.md](docs/api.md). `/glyphwork test` opens the demo, built with that API.

**Item icons:** 16 x 16 icons for 1595 items (in grids, buttons, lists, menus), drawn from the
textures every client already has. They follow your server's resource pack: replaced textures
are measured, and the pack's own items (`myserver:ruby`) work as icons.

**Menus without code:** server admins describe menus in YAML files (`plugins/Glyphwork/menus/`)
with buttons that run commands, open other menus or ask for input, PlaceholderAPI support and a
command per menu: [docs/menus.md](docs/menus.md).

Players without the pack get a plain native dialog built from the same scene. The pack is served by
a built-in HTTP server or written to `plugins/Glyphwork/pack/<sha1>.zip` for your own web server
(`pack.hosting: external`, `pack.url` with `{sha1}`). `/glyphwork reload` rebuilds theme and pack and
sends it to everyone online; `/glyphwork status` shows who has it. See `config.yml`.

**Skin editor:** https://flyingfinger1.github.io/Glyphwork/ ([guide](docs/skin-editor.md))

## Install

1. Download `Glyphwork-<version>.jar` from the [releases](https://github.com/flyingfinger1/Glyphwork/releases)
   into `plugins/` of a Paper 26.3 server (Java 25) and start it.
2. In `plugins/Glyphwork/config.yml` set `pack.url` to an address the players can reach: either the
   built-in server (open `pack-server.port`, e.g. `http://your.host:8765/{sha1}.zip`) or your own
   web server with `pack.hosting: external`. Then `/glyphwork reload`.
3. `/glyphwork test` opens the demo, `/glyphwork menu beispiel` the example YAML menu
   ([docs/menus.md](docs/menus.md)).

## Use it from your plugin

`plugin.yml`: `depend: [Glyphwork]`. Compile against `glyphwork-api-<version>.jar` from the same
release (do not shade it; the classes come with the Glyphwork plugin), e.g. with Gradle:

```groovy
dependencies {
    compileOnly files('libs/glyphwork-api-0.4.0.jar')
}
```

Then build scenes as shown in [docs/api.md](docs/api.md). Changes: [CHANGELOG.md](CHANGELOG.md).

## How it works (as verified against the 26.3 client)

- **x (P1):** font `glyphwork:space` maps private-use chars to advances of +-2^k px; any offset is a
  combination of them. All frames are layered on the **first text line** in paint order.
- **y (P2):** frames are drawn on the first text line; one font per pixel row (`glyphwork:y<N>`,
  N < `max-height`) registers every glyph sheet with `ascent = 7 - N`, so their paint order is exact.
  Text goes on the text line it falls into, with 9 fonts (`glyphwork:t0..8`) that re-register the
  vanilla text textures (`ascii.png` etc., not shipped) shifted by the remainder. Those textures are
  large and every font loads them again, so text gets only 9 fonts; text lines come after the first
  line, so text is always on top of frames. The pack depends only on the skin, not on the scenes.
  Empty lines make the text widget tall enough to receive clicks.
- **Clicks (P3):** the 26.3 client (`ActiveTextCollector.ClickableStyleFinder`) hit-tests each glyph
  against its *drawn* box (space glyphs: their line box) and the **last** glyph under the cursor that
  has a click event wins. So a sprite with a click event is clickable exactly where it is drawn, and
  glyphs without events (text labels, decorations) never block clicks. Invisible hitboxes are 8 x 8
  glyphs of alpha-1 pixels: the client does not draw them (alpha < 0.1) but they count for clicks. The line-binding problem from
  the original HugoSMP recipe does not apply to 26.3. `src/test/java/de/flyingfinger/glyphwork/M0HitTest.java` replays this logic.
- Text clicks in a dialog body run with the dialog's `afterAction`; we use `NONE`, so the screen
  stays open and the server answers with a re-rendered dialog.
- Bitmap advance = rightmost non-transparent column + 1 (same rule as the client).

## Skins

Frames (panel, button, slot ...) are autotiled from tiny A2 sheets, so any shape of cells joins
seamlessly. The built-in vanilla-style skin is generated by code and exported to
`plugins/Glyphwork/themes/vanilla/` on first start; own skins go next to it. Format:
[docs/skin-format.md](docs/skin-format.md).

## Skin editor

`editor/` is a standalone browser tool (plain HTML/JS, no build step), online at
https://flyingfinger1.github.io/Glyphwork/ ([guide](docs/skin-editor.md)), for drawing skins in the A2
format:

- **Paint in the window:** draw directly on a sample window of any shape; every pixel maps to its
  A2 quarter, so one stroke changes all places that use it (hover highlights them).
- **Generator:** outline, round corners, light/shadow width and color, fill, with presets for
  window, button and slot, as a starting point for hand painting.
- Pixel tools on the A2 sheet with a quarter overlay that names each part, optional mirroring.
- Live preview of any cell shape (with tint), all 47 generated tiles.
- **Demo scene:** the plugin's `/glyphwork test` screen rendered with the skin, clickable
  (own pixel font; the Minecraft font is not shipped).
- **Seams:** the 40 quarter transitions that are not neighbours in the A2 sheet, magnified, plus
  a test shape that contains all 68 possible transitions.
- Palettes: vanilla GUI colors, Minecraft text colors, own palette.
- ZIP import/export in exactly the folder layout the plugin loads; autosave in the browser;
  German and English UI.

```bash
py -m http.server 5280 --directory editor
```

Then open http://localhost:5280. `node tools/editor-parity.mjs` (after `./gradlew test`) checks that
the editor's JavaScript builds the same tiles as the plugin.

## Build & test

```bash
JAVA_HOME="/c/Program Files/Java/jdk-25.0.3" ./gradlew build
```

The tests replay the client's layout and hit test and write a preview of the demo screen to
`build/preview/demo.png` (text shown as bars).

`tools/extract_vanilla_text.py <client.jar> src/main/resources/vanilla_text.json` regenerates the
vanilla char grids and advances when Minecraft changes its fonts.
