# Glyphwork

Clickable, pixel-positioned GUIs inside the vanilla **dialog** screen (Paper 26.3), no client mod.
The whole GUI is one `plain_message`; the plugin generates a resource pack with bitmap fonts,
serves it from an embedded HTTP server and sends it on join. See [SPEC.md](SPEC.md).

**Status: M1** (primitives proven in a vanilla client, autotiled skins). A hard-coded demo screen
opens with `/glyphwork test`. The public scene API (M3) does not exist yet.

## How it works (as verified against the 26.3 client)

- **x (P1):** font `glyphwork:space` maps private-use chars to advances of +-2^k px; any offset is a
  combination of them. All elements are layered on the **first text line** in paint order.
- **y (P2):** one font per vertical offset (`glyphwork:y<N>`) registers every glyph sheet and the
  vanilla text textures (`ascii.png` etc., not shipped) with `ascent = normal - N`. Only offsets that
  are used get a font. The remaining lines of the message are empty and only make the text widget
  tall enough to receive clicks.
- **Clicks (P3):** the 26.3 client (`ActiveTextCollector.ClickableStyleFinder`) hit-tests each glyph
  against its *drawn* box (space glyphs: their line box) and the **last** glyph under the cursor that
  has a click event wins. So a sprite with a click event is clickable exactly where it is drawn, and
  glyphs without events (text labels, decorations) never block clicks. The line-binding problem from
  the original HugoSMP recipe does not apply to 26.3. `src/test/java/de/flyingfinger/glyphwork/M0HitTest.java` replays this logic.
- Text clicks in a dialog body run with the dialog's `afterAction`; we use `NONE`, so the screen
  stays open and the server answers with a re-rendered dialog.
- Bitmap advance = rightmost non-transparent column + 1 (same rule as the client).

## Skins

Frames (panel, button, slot ...) are autotiled from tiny A2 sheets, so any shape of cells joins
seamlessly. The built-in vanilla-style skin is generated by code and exported to
`plugins/Glyphwork/themes/vanilla/` on first start; own skins go next to it. Format:
[docs/skin-format.md](docs/skin-format.md).

## Skin editor

`editor/` is a standalone browser tool (plain HTML/JS, no build step) for drawing skins in the A2
format:

- **Paint in the window:** draw directly on a sample window of any shape; every pixel maps to its
  A2 quarter, so one stroke changes all places that use it (hover highlights them).
- **Generator:** outline, round corners, light/shadow width and color, fill, with presets for
  window, button and slot, as a starting point for hand painting.
- Pixel tools on the A2 sheet with a quarter overlay that names each part, optional mirroring.
- Live preview of any cell shape (with tint), all 47 generated tiles.
- ZIP import/export in exactly the folder layout the plugin loads; autosave in the browser;
  German and English UI.

```bash
py -m http.server 5280 --directory editor
```

Then open http://localhost:5280. `node tools/editor-parity.mjs` (after `./gradlew test`) checks that
the editor's JavaScript builds the same tiles as the plugin.

## Build & test

```bash
JAVA_HOME="/c/Program Files/Java/jdk-25.0.3" ./gradlew build
```

The tests replay the client's layout and hit test and write a preview of the demo screen to
`build/preview/demo.png` (text shown as bars).

`tools/extract_vanilla_text.py <client.jar> src/main/resources/vanilla_text.json` regenerates the
vanilla char grids and advances when Minecraft changes its fonts.

Config (`config.yml`): pack server bind/port/public URL, send on join, required, prompt.
